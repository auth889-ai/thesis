# Data / Scenario Specification

## A. Deterministic geometry + seeded stochastic demand

The unit-validation intersection is a four-arm, one-lane-per-direction, straight-through signalized junction. Geometry is generated from explicit SUMO node/edge/connection definitions.

Demand is generated by `scripts/generate_demand.py` using seeded exponential inter-arrival times. Two regimes create a controlled non-stationary test:

- first half: N/S demand > E/W demand
- second half: E/W demand > N/S demand

This is deliberate: a responsive controller should react to the demand reversal whereas fixed timing cannot adapt.

## B. Real-world Bologna/Acosta

Use the official `DLR-TS/sumo-scenarios` repository, pinned by commit SHA in `resources/UPSTREAM_LOCK.json`.

Run:

`bologna/acosta/run.sumocfg`

**unchanged first**. No local controller modifications are allowed before this upstream execution is captured.
