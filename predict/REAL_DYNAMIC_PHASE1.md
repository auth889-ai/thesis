# Phase 1 - Real Dynamic Traffic Prediction

This phase is the first priority. It proves traffic prediction on real dynamic
traffic time series before any routing claim is made.

## Data Policy

Use for model training and benchmark claims:

- `METR-LA` - real loop-detector speed time series, 207 sensors, 5-minute bins.
- `PEMS-BAY` - real Caltrans PeMS speed time series, 325 sensors, 5-minute bins.
- `PEMS03/04/07/08` - real PeMS traffic flow benchmark datasets, when added.

Use for runtime reference only:

- Google Routes live Dhaka calls. These may guide live advice at runtime, but
  Google route content is not persisted and is not used as ML training data.

Use as appendix only:

- `DHAKA_SIMULATED_SENSOR_GRAPH` generated by SUMO on the real Dhaka R1 road
  network. This is not real sensor data.

## Models

Minimum strong table:

- `STID`
- `Graph WaveNet`
- `DCRNN`
- `AGCRN`

Stretch:

- `STAEformer`
- `Chronos-Bolt` zero-shot

Each model must report MAE/RMSE/MAPE for 15, 30, and 60 minutes on at least
`METR-LA` and `PEMS-BAY`.

## Acceptance

Phase 1 is complete only when:

- `predict/results/benchmark.csv` exists.
- The table has at least 2 real datasets.
- The table has at least 3 models.
- Each row is produced by Colab/Drive logs, not local CPU training.
- `results/evidence_audit.py` marks the Colab benchmark as PASS.

Routing work starts after this, not before.
